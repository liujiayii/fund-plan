# 持仓详情页交易枢纽（Holdings Hub）设计

日期：2026-09-01 · 状态：已定稿待实施（叠在 `feat/order-cancel-amend` 之上）

## 背景与决策链

**为什么重构。** 撤单/改单上线后主人实测的反馈：功能「这一块那一块的」。
摊开看确实如此——买入有三个入口（自选行内抽屉 / 基金详情抽屉 / 持仓详情
内嵌面板），卖出只有一处且深（持仓详情页中部），定投独立成页与买卖割裂，
撤改单藏在订单时间线日期行末尾的小字里，订单又在首页 / 订单页 / 持仓详情
三处重复出现。根子是**三个枢纽在打架**：基金详情页、持仓详情页、订单页
各自长了点交易能力，谁都不是完整的家。历史上每期「哪近塞哪」，单看合理，
攒起来就碎。

**决策**（主人拍板）：

- 持仓详情页做**全功能交易枢纽**——单只基金的一切（仓位 + 买卖 + 定投 +
  该基金订单）收进一页
- 组织形式用 **antd Tabs 页签**（信息密度高、移动端友好），页签状态进 URL
- 撤单/改单**两处保留**（订单页 + 持仓详情页）且都做显眼
- 定投**基金视角 + 全局页并存**：定投可在无持仓时创建，纯持仓视角有盲区，
  `/me/dca` 保留跨基金总览

**不动买入抽屉**（2026-09-01-buy-drawer 刚定的形态）：自选页/基金详情页的
「看中就买」是场景入口，与本枢纽的「管理我的仓位」是两种用户意图，不冲突。

## 方案

### 1. 持仓详情页（`me.holdings.$code`）重构

```
┌────────────────────────────────────┐
│ ← 返回持仓   基金名 + 代码 + 标签    │
│ [持仓概览统计行]                     │ ← 顶部常驻（看仓位一眼全览）
│ [份额批次表]                        │ ← 顶部常驻（FIFO 费率可见性）
├────────────────────────────────────┤
│  [交易]   [定投]   [订单]           │ ← Tabs，激活页签写进 ?tab=
├────────────────────────────────────┤
│ 交易页签：加仓面板 / 卖出面板         │
│ 定投页签：DcaFundPanel              │
│ 订单页签：该基金全部订单 + 撤单/改单  │
└────────────────────────────────────┘
```

- 页签进 URL search param（`?tab=trade|dca|orders`，默认 trade）：
  持仓列表行的「卖出」可深链 `?tab=trade`，外链可直达订单页签
- 加仓/卖出面板与订单区块**原样迁入**页签，金融逻辑一行不动
- 页签切换是纯 UI 状态，不影响 loader（数据一次性全量返回）

### 2. 定投页签（新组件 `DcaFundPanel`）

| 件 | 职责 |
| --- | --- |
| `app/components/DcaFundPanel.tsx` | 该基金的定投计划卡片（状态/频率/金额/累计投入）+ 行内「暂停/启用/删除」 + 简化创建表单（金额 + 频率，基金代码锁定） |
| `dca-service` / `portfolio-service` | 新增按 (userId, fundCode) 过滤的计划查询；创建/启停/删除复用现有函数 |
| action | `me.holdings.$code` 的 action 增加 dca 分支，直接调用 `dca-service` 的 create/toggle/delete（intent 协议与 `/me/dca` 一致，基金代码取路由参数而非表单） |

- 全局 `/me/dca` 保留不动：跨基金统计 + 无持仓基金的定投在这里建

### 3. 撤单/改单显眼化

- `OrderActions` 从链接小字升级为**实底小按钮**（改单=默认色，撤单=红色），
  所有挂载处（订单页时间线、持仓详情订单列表）同步升级，样式改一处生效
- 订单页顶部新增「**待确认委托**」独立区块：pending 单以卡片呈现、操作按钮
  放卡片右侧——委托管理的主战场，不再与已成交历史混在一条时间线里

### 4. 各页角色定界（治「订单展示重复」）

| 页面 | 唯一职责 |
| --- | --- |
| 首页 `/me` | 五行概览（最近订单保持，入口角色） |
| 订单页 `/me/orders` | 全量委托管理：待确认区 + 历史时间线 |
| 持仓详情页 | 单只基金的一切（枢纽） |
| 自选页 / 基金详情页 | 「看中就买」场景入口 |
| 全局定投页 | 跨基金总览 + 无持仓定投 |

### 5. 持仓列表页（`me.holdings`）

行内操作升级为「详情 / 卖出」——卖出通过深链直达枢纽交易页签。行内不再
放买入（自选页/基金详情页已有场景入口，持仓行内再加就回到「到处都是」）。

## 不做的事（YAGNI）

- 不动买入抽屉形态
- 不做基金详情页卖出入口（卖前要看仓位与批次费率，枢纽在持仓页）
- 不合并三处订单展示，只让各司其职
- 不给订单页撤改单做批量操作

## 边缘与口径

- **无持仓基金的入口盲区**：定投在 `/me/dca` 建、买入在自选页/基金详情页，
  枢纽页只服务「已有持仓或已下过单」的基金——`me.holdings.$code` 的 loader
  对无持仓但有订单的基金照常渲染（现状已如此）
- **卖出面板显示条件不变**：可赎份额 > 0 且有批次才渲染；交易页签在无净值
  时只有加仓面板被净值守卫隐藏的现状保持
- **Tabs 与 SSR**：antd Tabs 客户端组件，默认页签由 URL 决定，SSR 与水合
  首帧读同一个 search param，无 mismatch
- **fetcher 成功信号**：面板下单仍走面板内部 fetcher + onSuccess 回调
  （buy-drawer 设计的教训：页面级 fetcher 是死信号）；DcaFundPanel 同款
- **测试**：新增的按基金过滤查询补 workers 测试；UI 重排无新金融逻辑，
  靠 typecheck + lint + 现有回归
